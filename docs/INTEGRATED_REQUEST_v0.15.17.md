# AUTOCHESS — 차기 통합 수정 지시서 (v0.15.15 이후 / Codex 전달용)

> **문서 목적:** 사용자 요청을 한 번에 전달하되, 기존 구현 완료분을 재작업하지 않도록 구분한다. **최신 실제 소스 코드와 패치노트가 규칙의 기준**이다. 본 문서는 요구사항이며, ChatGPT가 실제 게임을 실행하거나 버그를 확인했다는 뜻은 아니다.
>
> **입력 자료:** `AUTOCHESS_UI_COMPLETE_REFERENCE_AND_CODEX.zip`(아이콘 실에셋 5종·SVG·미리보기·HTML·UI 지시서), `AUTOCHESS_UI_COMPLETE_CODEX.md`, `AUTOCHESS_UI_MOTION_REFERENCE.html`, `AUTOCHESS_VFX_CODEX_IMPLEMENTATION.md`, 기존 게임 기획서/실제 소스. 첨부명에 `(1)`이 붙을 수 있으므로 **파일 내용 기준으로 식별**한다.
>
> **우선순위:** (1) 사용자 최신 확정 요청/본 통합 지시서의 명시적 예외 → (2) 제공된 UI·VFX 원본 레퍼런스(시각·타이밍) → (3) 현행 게임 코드의 실제 전투/경제/저장 규칙. 서로 충돌하면 규칙 변경 없이 이유를 보고한다.

## A. 작업 범위와 실행 순서

1. 최신 코드/버전·유대 데이터·이벤트 흐름·정적 에셋 경로를 확인하고 **기준 스냅샷** 기록.
2. **기존 UI 버그 3건 + 게임 시작 시 약 1초 지연 진단**을 우선 처리.
3. **첨부 UI 레퍼런스의 아이콘 5종, 액체형 인게임 XP 바, 전투 종료 HP 하트 충격형 1안**을 적용.
4. **VFX 원본 사양**을 적용하되 **회색=원거리 기본 공격, 노란색=녹스(C01) 스킬 전용**으로 한정.
5. **기존 28종 종족/직업/속성 조합 유대를 신규 테마형 16종으로 교체**하고 45명에게 유대 2개씩 배정. 종족·직업·속성 자체는 캐릭터 설정/스킬 분류로 보존.
6. 유대 16종의 **C안 혼합형 임시 밸런스 v1**을 구현하고 실제 테스트에서 튜닝 가능하도록 데이터화.
7. 회귀 테스트 후 변경 파일·결과·불일치·남은 미구현을 보고.

**주의:** 4~5코스트 12명은 제공된 기획서(v0.15.11)에서 미구현/도감 등록 상태였다. **이번 요청은 그 12명의 전투/상점 해금을 승인하는 것이 아니다.** 유대 데이터만 배정하고 기존 잠금 상태를 유지한다. v0.15.15 이후 달라졌다면 최신 코드를 우선 확인한다.

## B. 수정 요청 — 버그 및 실행 성능

### B1. 게임 시작 시 약 1초 지연 확인 및 개선 (신규)
- 사용자가 **게임 실행 시 약 1초 딜레이가 체감된다**고 보고함. 현재 원인은 **미확인**이며 고정 1초 지연이 있다고 단정하지 않는다.
- 진입 시점(페이지 로드→초기 화면 렌더→상호작용 가능→게임 시작 버튼→첫 준비 화면/전투)을 각각 계측하고, 사용자가 말한 '게임 실행' 구간을 실제 UX에서 재현한다.
- `performance.mark/measure`, Performance 패널, Long Task, 스크립트 평가·모듈 로드, 이미지 디코딩, 저장 복구, 데이터 초기화, 타이머/애니메이션 시작, Worker 생성/메시지 대기 등 원인을 조사한다.
- **의도하지 않은 1000ms 타이머/await/transition/초기화 블로킹**이 있으면 제거 또는 비차단 처리. 의도된 전환 연출은 함부로 삭제하지 말고 원인과 대안을 보고.
- 캐시 있음/없음, 첫 실행/재실행, 저장 있음/없음, 개발/배포 빌드, 탭 복귀에서 측정. 전후 수치(ms)와 측정 환경 보고. **게임 규칙·전투 타이밍을 빠르게 바꾸는 방식으로 해결 금지.**

### B2. 전투 결과창 닫힌 후 다음 적 배치
- 결과창이 열린 동안 **다음 스테이지 적 유닛이 전장에 나타나지 않도록** 렌더·상태 전환 순서를 수정.
- 내부 미리 계산은 허용하되 결과창 닫기 확정 후 다음 적을 노출. 중복 배치, 보스/보급 전환, 저장/로드, 백그라운드 복귀 점검.
- 보상·HP·스테이지 판정은 그대로.

### B3. 아이템 패널 과도한 빈 공간
- 기존 2열 일반 슬롯, 특수 슬롯 2개, 휴지통/복원, 스크롤 유지. 내부 높이·패딩·스크롤 영역·버튼 정렬을 콘텐츠에 맞춰 축소.
- 슬롯 자체를 무조건 다시 줄이지 말 것. **전투 딜량 그래프가 표시되어도 패널 하단이 잘리지 않아야** 하며 접기/펼치기·다양한 해상도 테스트.
- 기존 v0.15.15의 반응형 슬롯 56/52/44px 기능 회귀 금지.

### B4. 조합(유대) 패널 하단 돌출/잘림
- 스크롤 컨테이너 높이·`min-height:0`·`overflow`·하단 패딩·클리핑을 점검. 마지막 유대 행이 패널 안에서 완전히 보이고 클릭 가능해야 함.
- 유대가 28종→16종으로 바뀐 후에도 빈 상태·스크롤·접기/펼치기·리사이즈에서 정상 작동.

## C. UI 자료 — 첨부 파일대로 실제 적용

**에셋은 ZIP 안의 실파일을 사용.** ZIP에는 `icons/*.png` 5개, `source_svg/*.svg` 5개, `AUTOCHESS_ALL_5_ICONS_PREVIEW.png`, `AUTOCHESS_UI_MOTION_REFERENCE.html`, `AUTOCHESS_UI_COMPLETE_CODEX.md`가 들어 있다. HTML은 동작 시연용이며 실게임 로직을 복사하지 않는다. 단독 HTML에 보이는 상대경로 아이콘은 ZIP의 `icons/`와 함께 열어야 정상 표시된다.

### C1. 아이콘 5종
| 위치 | ZIP 내 원본 파일 | 의미 |
|---|---|---|
| 스테이지 일반 전투 | `icons/stage_battle_swords_64.png` | 교차 검 |
| 스테이지 보급 | `icons/stage_supply_chest_64.png` | 보물상자 |
| 스테이지 보스 | `icons/stage_boss_mask_64.png` | 악마 가면 |
| 설정 메뉴 | `icons/settings_gear_64.png` | 톱니 |
| 도감 메뉴 | `icons/codex_book_64.png` | 펼친 책 |

- PNG는 **64×64 투명 RGBA, 연보라 계열(#D0C6E0)**. 게임 정적 에셋에 복사하고 실제 경로 연결. 화면에서는 기존 크기/상태 표현에 맞춰 축소 표시.
- **기존 v0.15.15 스테이지 원형 노드 40px, 내부 아이콘 27px** 및 완료/현재/예정 구분·클릭·팝업 유지. 아래 라벨은 이미 제거된 상태이므로 복원 금지. 더보기 메뉴는 변경하지 않음.

### C2. 인게임 레벨 경험치 — 보라색 액체 게이지
- **기존 XP 바의 틀·텍스트·버튼·레벨 계산은 유지**, 내부 채움만 레퍼런스 HTML의 **2번 패널**과 같이 보라색 액체형으로 구현.
- 평상시 서로 다른 주파수의 물결 2겹과 미세한 반짝임 지속. 실제 XP 획득 시 0.5~0.7초 수위 상승, 파동 진폭 약 2.5~3배, 1초가량 출렁임과 도트 반짝임.
- 실제 레벨업 시 **꼭대기 수위→보라/흰색 섬광·도트 확산→다음 레벨의 잔여 XP 수위**. 다중 레벨업은 대표 연출로 간결하게, 입력 비차단.
- 실제 XP 수치/최대 레벨/XP 이월·저장 복구는 코드 기준. **HTML 데모 Lv.5·XP 필요량 계산식 `20+(Lv−5)×4` 및 데모 버튼을 게임에 이식 금지.** 로드/리렌더를 XP 획득 이벤트로 오인 금지.

### C3. 전투 종료 HP 하트 — 선택된 충격형 1안
- 레퍼런스 HTML **3번 패널**: 아래에서 상승하며 바운스·충격파(약 0~500ms) → 승리 민트/패배 빨강 충격 반응(약 500~900ms) → 실제 HP 전후 수치와 하트 내부 액체 수위 보간(약 900~1700ms) → 잠시 유지(약 1700~2800ms) → 축소·파티클 퇴장(약 2800~3450ms).
- **1안만 적용**. 마법진 소환형/액체 상승 등장형 등 다른 시안 금지.
- 실제 승리 회복/패배 피해량과 최대 HP를 사용. 레퍼런스의 **패배 −12, 시작 82HP는 데모값**. 회복량이 실제 0이면 `+2` 허위 표기 금지. 0HP 게임오버·결과창·딜량 그래프와 겹침/클릭 간섭 방지.
- 전투 결과 판정/보상/HP 계산은 변경하지 않고 기존 확정 이벤트에 시각 효과만 연결.

### C4. 공통 UI 애니메이션 규칙
- 선명한 사각 도트와 별도 부드러운 광원. 도트는 수명 종료 시 **개별 즉시 소멸**, 광원은 자연스러운 페이드 허용.
- `requestAnimationFrame` + 실제 경과 시간으로 보간. 전투 0.1초 틱/Worker와 분리. Canvas DPR·리사이즈·백그라운드·`prefers-reduced-motion`·타이머 정리 대응.
- 장식 레이어는 `pointer-events:none`; 기존 드래그/버튼/키보드 접근을 막지 않음.

## D. 전투 VFX — 원본 사양 + 최신 적용 범위

**반드시 동봉 `AUTOCHESS_VFX_CODEX_IMPLEMENTATION.md` 전체를 읽고** 투사체 막대 형태, 팔레트, 파티클 수·수명, 광원, 발사/명중 동기화, 성능 조건을 그대로 참조한다. 단 아래 적용 범위는 원본의 yellow 일반 공격 예시보다 우선한다.

| 테마 | 발동 조건 | 제외 조건 |
|---|---|---|
| **회색(gray)** | 실제 **원거리 기본 공격** 발사/비행/실제 명중 | 근접 기본 공격, 스킬, 원거리 판정 없는 공격 |
| **노란색(yellow)** | **녹스(C01)의 스킬** 실제 이벤트 | 녹스 기본 공격, 다른 모든 캐릭터의 기본 공격/스킬 |

- 원거리 여부는 **궁수 직업명이 아니라 실제 공격 타입/전투 이벤트**로 판단. 녹스의 원거리 기본 공격은 **회색만**.
- 녹스 스킬의 실제 구현이 즉시 타격이면 가상의 투사체/충돌 판정을 만들지 말고 실제 스킬 타이밍에 맞춘 효과만 연출. 불일치는 보고.
- 투사체는 **단순 직선 막대**. 화살촉/깃털/꼬리/트레일 없음. 발사·명중 시 정사각 도트+분리된 확산 광원. 도트는 알파 페이드가 아니라 개별 소멸.
- MISS/회피에는 명중 효과 없음. 중복 이벤트/연쇄 발동 금지. 공격 판정·피해·속도·스킬 타이밍은 절대 변경하지 않음. 전투 종료·일시정지·탭 복귀 시 정리.

## E. 신규 테마 유대 시스템 — 16종 (기획 수치 v1, 실제 적용 후 밸런싱)

### E1. 확정 구조
- 기존 종족 9·직업 9·속성/특성 10의 **캐릭터 설정은 유지**한다. 종족/직업/속성을 캐릭터에서 삭제하지 않는다.
- **기존 28종 종족·직업·속성 조합 보너스만 신규 16종 테마 유대로 교체**. UI/도감/추천/활성화 판정/저장·로드/증강/전투의 유대 참조를 일관되게 갱신. 과거 28종 효과가 동시에 적용되지 않게 한다.
- **전체 45명 각 유대 정확히 2개**, 5코스트 단독 고유 유대·3개 유대는 **보류(구현 금지)**.
- **C안 혼합형:** 2명=기본 능력치, 4명=능력치+특수 효과, 6명=강력한 완성 효과. 유대 단계는 **최고 활성 단계 하나만 적용**, 2/4/6 단계 누적합 금지.
- 기본 효과 대상은 **해당 유대원**. '인접 아군', '아군 전체' 등 명시한 경우만 예외. 서로 다른 캐릭터 ID당 1카운트; 성급/동일 캐릭터 복제에 의한 중복 카운트 금지(현행 유대 카운트 정책과 충돌하면 보고).
- **UI 공식 표시명은 2~4글자**(아르카나 4글자), 도감 설명에만 긴 콘셉트명 활용 가능. `월하`는 캐릭터 `월하(C40)`와 이름이 같으므로 **혼동 방지 표시** 검토하되 임의 개명 금지.

- **모든 수치는 임시 v1**. 엔진에 없는 기능은 조용히 생략하거나 대체하지 말고, 구현한 것과 불가능한 것을 항목별로 보고. 기존 36종 증강 중 종족/직업/특성 조합을 참조하는 것이 있다면 매핑 필요성을 보고하고 사용자 승인 없는 효과 변경 금지.
