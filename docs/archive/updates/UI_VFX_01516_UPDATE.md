결과 X/바깥 클릭은 라운드 진행을 확정하지 않습니다. 이 경우 결과 상태를 유지하여 적을 표시하지 않고, 기존 결과 확인 버튼으로 다시 열 수 있습니다. 다음 라운드 확정은 advanceRound가 성공한 경우에만 처리합니다. 결과창을 닫은 뒤 render를 호출하며, 같은 확정을 반복해도 라운드가 두 번 넘어가지 않습니다. 증강·보급·완료 상태도 prepare가 아니므로 적을 노출하지 않습니다. 전투 마무리 중 남은 유닛은 기존 CombatView가 처리하고, 이 유닛들을 다음 적 배치와 섞지 않습니다.

기존 일반 공격 VFX는 아군·적군·소환수 모두의 실제 원거리 공격에 적용되어 있었으므로 회색도 이 범위를 사용했습니다. 직업·이름 문자열로 분류하지 않았습니다. E01이 녹스와 같은 스킬 함수를 재사용해도 정확한 ID가 C01이 아니므로 노란 테마를 배정하지 않습니다. I27로 실제 추가 시전이 발생하면 각 직접 명중은 별도 이벤트이므로 각각 한 번 표시됩니다.

녹스 스킬은 현재 엔진에서 즉시 AD160% 직접 피해를 준 뒤4초 화상을 적용합니다. 실제 발사·충돌 상태나 비행 시간이 없습니다. 따라서 이번 요청의 제한에 따라 노란 비행·투사체 판정을 새로 만들지 않았습니다. 노란색은 직접 명중 순간의 버스트로 적용했습니다. 원본 문서의 노란 막대 비행은 현재 녹스 스킬과 직접 매핑할 수 없는 항목입니다.

회색 비행은 기존 표시용65~210ms/배속 계산을 재사용합니다. 게임의 피해와 HP는 기존 엔진 시점에 즉시 반영되며, 화면에서는 막대가 도착할 때 명중 버스트·피격 반응·피해 숫자를 함께 보여 줍니다. 시각 비행 때문에 실제 HP 차감이나 공격 주기를 늦추지 않습니다. 모든 전투 계산·명중·보상·Worker의 시간 진행 코드는 그대로 사용합니다.

별도 vfx-events 어댑터가 deal/log 호출에서 공격 순간 좌표와 회피 공격자를 읽어 visual 메타데이터를 추가합니다. 난수나 수치를 수정하지 않습니다. 고유 표시ID로 같은 이벤트 재소비를 차단하고, 해당 칸의 보정된 화면 중심 좌표를 사용합니다. 비행 중에는 requestAnimationFrame의 경과 시간을 사용하고, 화면 크기가 바뀌면 잔여 효과를 지워 이전 좌표가 남지 않게 합니다.

두 테마는 같은 프로필을 사용합니다. 막대는32×8 기준과 내부 단색 코어이며 화살촉·깃털·탄피·비행 꼬리가 없습니다. 도트는 발사14개/명중22개, 발사135~270ms/명중145~360ms 수명을 사용합니다. 살아 있는 도트는 globalAlpha 1로 정수 좌표에 그리며, 수명이 지나면 배열에서 제거합니다. 광원만 별도 lighter/방사형 그라데이션으로 표시하고 남은 도트 개수에 연동합니다. 중심 광원 반경40/56, 최대 강도0.7, 개별 광원0.18은 Codex가 시각 확인 후 정한 값입니다.

동시 상한은 도트720개, 막대64개, 중심 광원48개입니다. 도트 객체를 재사용하고 외곽 픽셀의 광원을 생략합니다. 리사이즈·전투 종료·단계 전환은 Canvas와 잔여 상태를 정리합니다. 수동 정지와 탭 가시성 변경은 진행 중 효과를 비웁니다. 500ms 이상 지난 시각 이벤트는 복귀 시 재생하지 않습니다. 요청된 픽셀 경로에는 기존 금색 치명타 링/근접 슬래시를 중복 추가하지 않으며 치명타 피해 숫자는 유지했습니다. 다른 스킬·근접 공격의 기존 연출은 유지했습니다.

19개 스위트286개 검사가 통과했습니다. 신규5개 검사는 다음 항목을 확인합니다.

- 33명 각각을 같은 RNG 조건으로 VFX 어댑터 설치 전후 비교하여 결과·최종 유닛·visual 필드를 제외한 로그 순서와 수치가 동일함.
- 공격 순간 좌표와 회피 공격자를 보존하고, 나중에 유닛이 이동해도 해당 표시 좌표가 바뀌지 않음.
- 회색 일반 공격과 C01 직접 스킬 노란 효과의 배정이 겹치지 않으며, 근접·DOT·아이템 피해·다른 스킬에는 잘못 연결되지 않음.
- 도트 불투명도1 유지·개별 삭제, 한 비행당 한 번의 명중, MISS 명중 없음, 중복ID 방지, 상한·리사이즈·잔여 상태 정리.
- 일반/보스/보급 결과를 저장·불러온 경우도 적이 없고, 다음 확정 후 창이 닫힌 다음에만 적을 한 번 배치함.

기존 전투·경제·유대·아이템·저장 회귀 검사와 전투 Worker의 일반/보스×1/2/4배속 검사를 유지했습니다. 실제 게임에서는 결과창 열기/닫기/확정, 원거리 다수 동시 공격, 보스 전투, 리사이즈, 아이템40개 스크롤, 빈 보관함, 드래그 장착, 패널 반복 접기/펼치기를 확인했습니다. 보관함1개 아이템을 실제 드래그로 장착한 뒤 보관0개/빈1행으로 표시되는 것도 확인했습니다. 수동 정지 시1.9초 시계가 유지되고 효과 레이어는 Canvas 한 개만 남은 상태를 확인했습니다. 브라우저 콘솔 오류·경고는0건입니다.

자동화의 별도 탭을 열어도 대상 페이지의 document.hidden이 false/visible로 유지되어 실제 숨김·복귀 조건은 이 브라우저 환경에서 재현되지 않았습니다. 이 조건은 자동화 실측 완료로 적지 않습니다. 정리 함수와 오래된 이벤트 폐기는 코드 검사로 확인했습니다. 캔버스의 실제 getImageData 읽기는 자동화 DOM API가 제공하지 않아 수행하지 못했으며, 픽셀의 alpha 검사는 그리기 호출 검사와 실제 화면 확인으로 나누어 검증했습니다. GIF/동영상은 만들지 않았고 연속 JPEG 프레임과 화면 캡처를 저장했습니다.

주요 증거 파일은 outputs/autochess-v0.15.16-panels.jpg, outputs/autochess-v0.15.16-metrics.json과 vfx16-battle-*.jpg, vfx16-gray-*.jpg, vfx16-yellow-*.jpg입니다. 검증용 원정과 VFX 검증 화면은 로컬 테스트 서버에서만 제공했으며 배포 소스에 넣지 않았습니다.

새 토스트나 확인창은 추가하지 않았습니다. 이번 표시 결정과 제한은 패치노트의 Codex 판단·알림/팝업 항목에도 기록했습니다. 기존 장비 수량 테스트는 무작위 P11 증강이 별도 장비2개를 주어 검사 수량이 흔들리는 문제를 발견해, 그 테스트에서만 P11을 선택하지 않도록 안정화했습니다. 게임의 증강 후보·지급 규칙은 변경하지 않았습니다.
