# AUTOCHESS — 다음 버전 수정 및 문서화 요청서

> 기준: 현재 Codex 작업 트리의 실제 소스코드와 데이터. 버전 번호는 코드에서 확인하여 기록할 것.
> 목적: 아래 UI 수정 4건과 기획·개발 현황 문서 4종 작성.
> 주의: 문서 작성 작업은 게임 기능이나 밸런스를 변경하지 않는다. UI 변경도 명시한 범위에 한정한다.

## A. UI 수정사항

### 1. 아이템 UI의 '칸' 축소
- **아이템 패널 전체 폭을 줄이라는 뜻이 아니다.**
- 아이템이 들어가는 **개별 칸(슬롯)**의 가로 크기 또는 좌우 여백을 줄여 더 좁게 표시한다.
- 슬롯의 세로 크기와 아이템 이미지 크기를 변경해야 하는지는 기존 레이아웃을 먼저 확인하고, 요청하지 않은 확대·축소는 하지 않는다.
- 2열×6행, 초과 아이템 스크롤, 특수 2칸, 장착·해제·삭제·복원 등 기존 동작을 유지한다.
- 슬롯 축소 시 클릭/드래그 영역, 아이템 이미지, 툴팁, 패널 정렬이 깨지지 않도록 확인한다.
- **기존 패치의 '패널 폭 축소'와 혼동하지 말 것.**

### 2. 전투 승패 시 중앙 체력 변화 연출
- 전투 승리 또는 패배 시 **화면 중앙**에 현재 플레이어 체력을 나타내는 애니메이션을 표시한다.
- **빈 하트 형태를 기본으로, 경험치 막대처럼 누적량이 보이는 바(막대 그래프)** 형태를 사용한다.
- 승리 시 체력 회복분만큼 하트/바가 차오르고, 패배 시 체력 손실분만큼 비거나 떨어지는 연출을 보여준다.
- 전투 전·후 체력 값과 변화량을 시각적으로 이해할 수 있어야 한다.
- 현재 적용된 체력 증감 규칙, 최대 체력, 패배 연출과 충돌하지 않도록 실제 코드의 최신 규칙을 확인한다.
- 실제 HP 정산과 시각적 연출은 분리하며, 전투 결과·저장 데이터에 영향을 주지 않는다.
- 모션 감소 설정, 빠른 화면 전환, 연속 전투, 배속과의 호환성을 검토한다.
- **구현 난이도가 높거나 기존 구조와 충돌한다면 임의로 구현하지 말고 먼저 사용자에게 문제와 대안을 보고한다.**

### 3. 상단 스테이지 진행 UI 확대
- 상단 진행상황 UI를 **전체적으로 크게** 만든다.
- 가로 방향으로 더 넓게 배치하여 좌우 공간을 활용한다.
- 각 원형 스테이지 노드와 내부 아이콘(보급 상자·일반 전투 쌍검·보스 악마 머리)도 함께 확대한다.
- 현재/완료/예정 상태, 노드 순서, 스테이지 기능은 유지한다.
- 화면 크기 변화 시 겹침·잘림·가로 스크롤 문제가 없는지 확인한다.
- 구체적인 확대 배율은 실제 레이아웃을 확인해 자연스럽게 조정하고 결과를 보고한다.

### 4. 라운드 종료 → 다음 라운드 전환 연출
- **한 라운드가 끝날 때** 화면 전체를 덮는 전환 연출을 추가한다.
- 전체 화면 오버레이를 사용하여 다음 라운드로 넘어간다는 사실을 분명하게 표현한다.
- 중앙에 다음 라운드 번호를 `ROUND N` 형태로 표시하는 방안을 우선 검토한다.
- 전환 타이밍은 기존 전투 결과·보급·증강·보스 처리 및 모달과 충돌하지 않도록 조정한다.
- 기존에 구현된 라운드 표시 연출이 있다면 중복 재생하지 말고 통합·확장한다.
- 애니메이션 도중 입력, 일시정지, 장면 전환, 모션 감소 설정을 안전하게 처리한다.
- 실제 라운드 진행·보상·저장 규칙은 변경하지 않는다.

## B. 프로젝트 문서 4종 작성

현재 AUTOCHESS 프로젝트의 **전체 소스코드, 기획 데이터, 기존 패치노트**를 분석해 아래 4개의 Markdown 문서를 생성한다. 단순히 이 요청서를 바탕으로 추측해 채우지 말고, 실제 프로젝트 파일을 조사해야 한다.

### 1. `AUTOCHESS_GAME_DESIGN.md`
- 현재 게임의 전체 기획서
- 전투, 캐릭터, 종족, 직업, 특성, 경제, 성장, 아이템, 증강, 스테이지 등 **모든 시스템의 상세 규칙**
- 캐릭터 **45명의 전체 데이터와 스킬** (미구현 캐릭터도 기획 데이터가 존재하면 구분해 수록)
- 각 조합의 발동 조건과 효과
- 구현된 규칙과 기획만 확정된 규칙을 구분

### 2. `AUTOCHESS_GLOSSARY.md`
- 게임에서 사용하는 모든 용어와 약어
- 능력치 및 데미지 계산에 사용되는 변수
- 종족, 직업, 특성의 정확한 명칭과 정의
- 상태이상 및 전투 효과의 정의
- 코드 내부 명칭과 화면 표시 명칭이 다르면 양쪽을 대응시켜 기록

### 3. `AUTOCHESS_UNIMPLEMENTED.md`
- 아직 구현되지 않은 콘텐츠
- 임시 구현된 시스템
- 기획은 존재하지만 실제 효과가 적용되지 않는 요소
- 추후 결정이 필요한 규칙
- 가능하면 관련 소스 위치와 미구현 판단 근거 기록
- 구현 여부를 확인할 수 없으면 **'확인 필요'**로 표시

### 4. `AUTOCHESS_CHANGELOG.md`
- 기존 패치노트와 버전별 변경 이력 정리
- 실제 코드와 패치노트의 차이가 발견되면 별도 섹션에 기록
- 이전 버전의 변경과 현재 상태를 혼동하지 않도록 구분

## C. 문서 작성의 필수 원칙

1. **실제 소스코드와 현재 적용된 데이터를 최우선 기준**으로 삼는다.
2. 기존 패치노트와 코드가 충돌하면 **차이점을 별도로 기록**한다. 근거 없이 어느 쪽도 조용히 덮어쓰지 않는다.
3. 확인되지 않은 규칙이나 수치를 **임의로 만들어 내지 않는다**.
4. **확정된 기획 / 임시 수치 / 미구현 요소 / 확인 필요**를 명확히 구분한다.
5. **문서 작성 때문에 게임 기능이나 밸런스를 수정하지 않는다.** 위 A항의 UI 변경만 별도 허용한다.
6. 기존 기획 정보가 누락되지 않도록 가능한 한 상세히 작성한다.
7. 문서에 최신 코드의 파일 경로·상수·데이터 정의를 근거로 남기면 추후 유지보수에 도움이 된다.
8. 4개 문서의 내용이 서로 충돌하지 않도록 용어·버전·구현 상태를 교차 검토한다.
