# AUTOCHESS v0.11 — 증강 시스템 구현 명세서 (Codex 전달용)

> **목적:** 현재 동작하는 v0.10 웹 프로토타입에 아래 확정 증강 규칙과 36개 증강을 추가한다. 이 문서는 **구현 요청서**이며, 구현 완료를 의미하지 않는다.
>
> **우선순위:** 사용자 확정 사항 및 본 문서의 v0.11 변경 사항 > 첨부 `AUTOCHESS_PATCH_NOTES_v0.10 (1).md`의 현재 규칙 > 과거 패치 이력. 명시하지 않은 정상 기능은 변경하지 않는다.

## 1. 요구 사항 요약

- 한 번의 원정에서 **3회** 증강 선택: **1-3 / 3-3 / 5-3 노드에 진입하기 직전**.
- 각 회차마다 등급 **실버 / 골드 / 프리즘을 독립적으로 동일 확률(각 1/3)**로 1개 추첨한다.
- 선택된 **단일 등급**의 증강만 **서로 다른 3개** 무작위 제시하고, 플레이어가 **1개 선택**한다. 서로 다른 등급이 한 화면에 섞이면 안 된다.
- 이미 **선택한 증강 ID는 이후 모든 회차의 후보에서 제외**한다. 단, 이전 회차에 제시만 되고 선택되지 않은 증강은 재등장 가능하다.
- 등급 자체는 중복될 수 있다. 예: 실버→실버→실버, 실버→프리즘→골드 모두 가능.
- 선택한 효과는 **해당 원정이 끝날 때까지** 적용한다. 새 원정을 시작하면 초기화한다.
- 세 차례 모두 **증강을 선택하기 전에는 다음 노드 진행 불가**. 기존 증강 시점인 **2·4·6구간 시작** 이벤트는 제거/교체한다.
- 증강 **실버 12개(S01~S12), 골드 12개(G01~G12), 프리즘 12개(P01~P12)**, 합계 **36개**를 추가한다.
- 플레이어 의도: 강력한 시너지/중첩은 허용한다. 증강 사이의 성능을 균등화하기 위한 별도 밸런스 조정은 이번 범위에 없다. **효과 동작과 게임 안정성 검증은 필수**.

## 2. 현재 v0.10과의 접점 (기존 동작 보존)

- 싱글 PvE, 8×8 보드, 아군 아래 4줄, 동일 캐릭터 ID 전장 1명 제한.
- 인게임 Lv3~10, 레벨=배치 한도(기본 최대 10명), 4G에 4XP, 라운드 자동 2XP는 기존 테스트 값.
- 상점 5칸, 새로고침 2G, 이자 10G당 1G/최대 5G, 일반 승/패 3G/1G, 보스 승/패 5G/3G, 연승 보너스 최대 +5G.
- 보스 승리 확정 아이템 1개 (R1=T1, R2~4=T2, R5+=T3) 및 **기존 보스 추가 골드 확률/금액** 보존.
- 40개 장비(I01~I40), 보급 4개 제시→2개 선택, 보물 슬라임, 합성/판매/저장/복원 등 기존 로직 보존.
- v0.10 노드 규칙: `R-S`의 `R`은 상위구간, `S`는 해당 구간의 1~5 노드. `1-1`/`1-2`는 보급; 이후 구간의 `R-3`은 보급, `R-5`는 보스. **증강은 노드 종류와 무관하게 1-3, 3-3, 5-3에 들어가기 전에** 나타나야 한다. 특히 `3-3`, `5-3`을 무조건 일반 전투로 간주하거나 기존 보급을 삭제하지 않는다.
- 실제 해금된 캐릭터는 C01~C23(1·2코스트); 나머지 3~5코스트는 비활성. 이 작업으로 임의 해금하지 않는다.

## 3. 진행 순서 및 추첨 규칙

1. 현재 진행상 다음 진입 노드가 `1-3`, `3-3`, `5-3` 중 하나이고 그 회차 증강을 아직 선택하지 않았다면 **노드 진입 처리보다 먼저** 증강 선택 창을 연다.
2. 매 회차 진입 시 **등급을 새로** 1/3씩 독립 추첨한다. 이전 추첨 결과나 라운드, 플레이어 상태를 이용한 확률 보정/천장/등급 고정은 없다.
3. 그 등급에 속한 증강에서 이미 선택된 ID를 빼고 3개 서로 다른 ID를 무작위로 뽑는다. **모든 후보는 동등한 추첨 확률**로 취급한다.
4. 플레이어가 3개 중 1개를 확정하면 선택 결과를 저장하고 효과를 반영한 뒤 해당 노드 진입을 허용한다.
5. 이미 뽑힌 등급과 3개 선택지는 닫기/새로고침/재접속/이어하기로 바뀌지 않아야 한다. 반복 보상이나 중복 획득이 발생하면 안 된다.
6. 한 원정에서 각 증강 회차의 확정 선택은 정확히 1회만 가능하며, 최대 3개를 보유한다.

**예시:** 1-1 보급 → 1-2 보급 → **[첫 증강 선택]** → 1-3 진입. ... → **[두 번째 증강 선택]** → 3-3 진입. ... → **[세 번째 증강 선택]** → 5-3 진입.

## 7. 효과 처리와 저장 — 구현 지침

### A. 효과 적용 시점
- `선택 즉시` (S09, S10, G10, G11, P09의 즉시 골드, P10, P11): **선택 확정 이벤트 한 번에만 지급**. 저장 데이터의 선택 완료 상태와 같은 트랜잭션 관점으로 처리해 새로고침/복원 후 재지급 방지.
- `지속 경제 효과` (S11, G12, P09 승리 보너스): 선택한 시점 이후에만 적용. 이미 끝난 전투/상점 새로고침에 소급 적용하지 않는다.
- `지속 능력치 효과` (S01~07, S12, G01~05, P01~03, P08 등): 전투 시작 시 배치된 유닛과 이후 동일 원정에서 사용하는 대상 유닛의 실효 능력치에 반영; 전투마다 재생성되는 유닛에 효과가 사라지지 않게 한다. 원본 캐릭터 기본 데이터에 영구 누적해 저장하지 않는다.
- `전투 발동형 효과`: 각 전투에서 새로 타이머/중첩/쿨다운/전투당 1회 여부를 초기화하고 해당 전투에만 발동시킨다.
- 이미 다른 스킬/아이템 시스템에 있는 보호막, 회복, 피해량, 타이머, 상태 저장 처리와 최대한 동일한 계산/이벤트 흐름을 사용한다. 효과 적용 시 기존 장비/스킬을 깨뜨리지 않는다.

### B. 저장 구조(예시, 실제 코드에 맞게 조정)
```js
run.augments = {
  selectedIds: [],               // 최대 3개, 이미 선택한 증강 ID
  completedPicks: [],            // 예: ["1-3", "3-3"]
  pendingPick: null              // 예: { node: "5-3", tier: "gold", optionIds: ["G02", "G05", "G12"] }
};
```
- 기존 세이브에 `augments`가 없으면 **안전한 초기 상태로 마이그레이션**하되 해당 진행 구간을 이미 통과했다면 과거 증강을 소급 지급하거나 진행을 되돌리지 않는다. 이관 방법은 현재 세이브 구조에 맞추고 기존 원정이 손상되지 않도록 한다.
- 제공된 선택지와 미확정 상태를 저장하고, 선택 확정 후에는 `selectedIds`와 `completedPicks`를 반영하여 `pendingPick`을 제거한다.
- 즉시 보상 중복 지급이 없도록 확정 처리 전체를 원자적으로 관리한다. 지급 전에 세이브 중복 처리 여부를 확인한다.

### C. UI
- 기존 어두운 화면 스타일과 상호작용 방식을 유지. 이미지 리소스/캐릭터 일러스트 신규 생성 불필요.
- 증강 선택 화면: 현재 회차(1/3, 2/3, 3/3), 등급명/색상, 같은 등급의 증강 카드 3개, 이름, 전체 효과 텍스트, 선택 확정 조작.
- 등급 색상 예시: 실버 회색, 골드 금색, 프리즘 보라/오색 계열. 시각 요소는 CSS로 충분하며 이미지 최소화.
- 선택한 증강 1~3개의 목록과 효과를 원정 UI에서 다시 확인할 수 있어야 한다.
- 미선택 상태로 다음 노드에 진입하거나, 중복 클릭으로 2개 선택하는 일이 없어야 한다.

## 8. 모호한 세부 동작에 대한 구현 유의사항

다음은 **새로운 밸런스 변경을 확정한 것이 아니라**, 기존 제안서의 문구와 현재 코드에서 충돌할 수 있어 주의가 필요한 점이다. Codex는 **효과를 임의 교체하지 말고** 현행 코드의 관련 수치를 확인해 일관되게 처리하며, 판단이 필요한 곳은 구현 보고서에 기록한다.

1. **S07/G03/P03:** 원 설계는 명시적으로 `최대 MP -10%/-20%`이다. `마나 소모량 감소`나 `스킬 비용 감소`로 자동 변경하지 말 것. 최대 MP, 현재 MP, 스킬 발동 문턱에 대한 기존 구현을 확인하고 0 이하/NaN/무한 반복만 안전하게 방지할 것.
2. **P12:** Lv10+P12에서 11명 배치가 가능하도록 8×8의 아군 구역, 전장 배치 검사, UI 카운터를 확장하되 **일반 최대 레벨 10**과 기본 한도는 그대로 유지한다. Lv3~9에서는 기존 레벨별 배치 한도 +1.
3. **P11:** 아이템은 기존 T3 15개(I26~I40) 및 보관함 추가 경로를 재사용. 같은 ID가 두 번 나오는지에 대한 구체 규칙은 원안에 별도 명시가 없으므로 기존 아이템 추첨 규칙을 따르고 정책을 보고한다.
4. **P04 vs I28:** 전투당 1회 생존 효과가 중복될 경우 각각 독립 상태인지, 발동 우선순위가 무엇인지 명시하고 동일 치명타에 두 효과가 비정상적으로 동시 소모되지 않게 할 것. 임의로 아이템 효과 삭제/변경하지 말 것.
5. **G07:** 5, 10, 15, 20초 도달 시 최대 4중첩. 별개의 전투에서 중첩이 이어지지 않게 한다.
6. **P06:** 전투 시작 10초 후 *그 시점에 생존 중인* 아군에 1회 적용. 반복 누적 아님.
7. **G08:** 스킬 후 최대 MP의 15%를 회복하며 캐릭터별 5초 쿨다운. 스킬과 아이템 추가 발동의 이벤트 출처/재귀 규칙에 맞게 처리한다.
8. **CTC·CTH·DOD:** 기존 확률·치명타 계수 시스템 및 `%` vs `%p` 표현을 일치시킨다. `+15%p`는 곱셈 `×1.15`가 아닌 백분율 포인트 가산이다.
9. **보호막/흡혈/아이템 고유 효과:** 효과가 의도적으로 같이 작동하도록 하되, 재귀 발동/중복 보상 오류는 방지한다. 피흡은 실제 피해량 기반, 회복은 최대 HP 제한을 준수한다.
10. **전체 아군 범위:** 기존 전투 엔진에서 일반 전장 아군과 소환수를 어떻게 구별하는지 확인. 기존 팀 버프 규칙과 일치시키되 소환수 처리 방식은 구현 보고서에 명시한다.

## 10. Codex 작업 지시

1. **먼저 프로젝트 실제 소스를 확인**해 v0.10의 증강/진행/전투/저장 구조를 파악한다. 이 명세서에 있는 의사 구조를 그대로 강제하지 않는다.
2. 증강 데이터 36종을 ID 기반으로 등록한다. 모든 효과는 **실제 전투/경제 로직**에 연결하며 화면 텍스트만 추가하는 구현은 불가하다.
3. 노드 진입 직전 3회 트리거, 독립 등급 추첨, 3개 선택지, 기선택 ID 제외, 확정/저장/복원, 결과 UI를 통합한다.
4. 단위/통합 테스트가 가능하면 위 체크리스트 기준으로 테스트한다. 시뮬레이션을 통한 증강 간 강도 비교나 너프는 요청 범위가 아니다.
5. 완료 시 **변경된 파일 / 핵심 구현 / 테스트 결과 / 남은 모호점 또는 제한**을 간단히 보고하고, 패치노트에 v0.11 변경 이력을 추가한다.
