# AUTOCHESS v0.15.12 — 체스판 교체·화면 좌표와 UI 개선

작업 기준: v0.15.11 소스 커밋 `6c14d1782f4335702bcb014de09286a4e8897895`. 최초 6×7 첨부 이미지는 적용하지 않고, 사용자가 다시 제공한 `석조 아치형 7×8 빛나는 격자 보드.png`를 적용했습니다. 이미지는 재생성·편집·비율 변형 없이 그대로 복사했습니다. 기존 풍경 배경·원본 보드·패널·저장 데이터는 보존했습니다.

## 1. 이미지와 56칸 좌표

- 원본: 1659×948 PNG, 비율 1.75:1. 투명 여백을 포함한 원본 전체를 같은 배율로 표시합니다.
- 세로선 중심 X: `283.5,443.5,600,754.5,909.5,1063,1215,1375.5`.
- 가로선 중심 Y: `94,186.5,277,366,453,542,628,719.5,813`.
- 밝은 선의 R>135/G>210/B>230 픽셀을 여러 행/열에서 측정했습니다. 7열×8행, 아군 하단 4행은 그대로이며 각 간격을 별도 CSS fr 트랙으로 반영했습니다. [측정과 원본 SHA-256](docs/BOARD_01512_CALIBRATION.json).
- 보드 크기는 화면 높이와 좌우 패널 폭 중 더 엄격한 제약으로 결정합니다. 좌우 여백이 비대칭이면 남은 공간의 중앙에 둡니다. 논리 칸 수를 바꾸거나 이미지를 강제로 늘리지 않습니다.
- 1366×768에서 원본 영역 약872×498.3px, 입력 격자 약574×377.9px. 석조 이미지 영역과 좌우 패널 사이 각16px 이상, 아래 대기석과도 분리됩니다. 1920×1080에서 약1426×814.8px입니다.
- 390×844에서 접힌 패널 사이 보드 약274×156.6px. 오른쪽 패널을 펼치면 보드120×68.6px로 줄어 겹치지 않습니다. 왼쪽 펼침도 확인했습니다. 작은 화면에서는 보드가 작아지므로 기존처럼 데스크톱 플레이에 더 적합합니다.

## 2. 요청 UI와 표시 조건

| 항목 | 현재 구현 |
| --- | --- |
| 중앙 HP | 네모 배경/외곽선/체력 막대/전투 전후·증감·최대치 문구 제거. 하트와 현재 체력 숫자만 표시. 하트 채움/비움은 유지 |
| 구간 내 이동 | 1-1→1-2, 2-1→2-2 등은 `STAGE 1-2` 텍스트만, 1600ms. 배경 덮기·입력 차단 없음 |
| 상위 라운드 이동 | 1-5→2-1 등에서만 `ROUND 2`와 전체 화면 좌→우 채움. 2200ms로 기존1300ms보다 확대 |
| 아이템 UI | 일반/빈칸/특수2칸 모두44×28px. 직전 일반87×56px의 약 절반. 아이콘18px. 휴지통/복원 버튼도44×28px. 패널 폭·기본12칸·2열·초과 스크롤 유지 |
| 패치노트 | 설정에 진입 버튼 복원. 시작 화면/더보기의 기존 진입, 복사·MD 저장·글꼴 테스트 유지 |

실제 HP 정산·저장은 먼저 끝나고 중앙 표시 후 기존 결과창으로 이어집니다. 중앙 체력1500ms/모션 감소500ms는 유지했습니다. 모션 감소 시 스테이지350ms·라운드600ms 페이드이며 화면 채움 이동은 생략합니다. 증강 선택을 거치는 스테이지는 선택 완료 후 표시하고, 결과/보급/6-5 완료 선택과 중복 실행하지 않습니다. 새 원정/시작 화면/리사이즈/탭 숨김 시 기존 취소·정리 경로를 유지합니다.

## 3. 별도 판단으로 추가·조정한 사항

- 1600/2200ms 및 모션 감소350/600ms는 요청의 ‘시간을 살짝 늘림’을 구체화한 표시값입니다. 체력1500ms는 유지합니다.
- 720px 이하에서는 펼친 패널의 폭만큼 보드를 더 줄이고 반대 패널을 접습니다. 두 패널을 연 상태에서 화면을 좁혀도 둘을 동시에 펼쳐 보드 공간이 사라지지 않게 정리합니다. 전투/아이템 판정에는 영향 없습니다.
- 이미지의 불균일한 선 간격을 평균으로 뭉개지 않고 각각 반영했습니다. 원본 전체 비율을 사용해 프레임 자체를 왜곡하지 않습니다.
- 일반/특수 칸 정렬, 작은 아이콘/번호, 휴지통/복원 버튼 크기를 함께 맞췄습니다. 패널 자체의 폭은 유지했습니다.
- 공통 알림 T01~T41 정책과 문구는 변경하지 않았습니다. 스테이지 텍스트는 전환 표시를 대체하며 새 토스트가 아닙니다. 중앙 체력의 부가 정보는 기존 결과창에서 계속 확인할 수 있습니다.

이 항목들은 인게임 패치노트와 ChatGPT 전달용 MD의 `Codex 판단으로 추가·조정한 사항`, `알림·팝업·표시 조건 변경`에 별도 기록했습니다.

- `node test-all.cjs`: **17개 스위트 278개 검사 통과**. 실제 CombatView의 56칸 측정·위치 계산을 여러 배율로 검사하고, 원본 PNG 해시/크기, 스테이지/라운드 분기, 텍스트 입력 비차단과 취소도 검증합니다.
- 실제 브라우저 1280×720에서 이미지 선과 모든56칸의 좌/우/상/하 경계 대조: 최대 오차 약0.024px. 원본 선 중심 측정의 약1px 수준 불확실성은 별도입니다.
- 대기석 동료를 실제 드래그로 pos31/32/55(5행 중앙,8행 우측 모서리 포함)에 배치. 캐릭터와 칸 중심 오차0~0.008px.
- 실제 전투에서 이동 목적지 중심 오차 약0.0005px, 유닛8개·피해숫자5개·투사체3개·스킬 이펙트17개가 함께 표시되는 장면 확인. 이펙트와 유닛은 기존 DOM 측정값을 공유하며 AI나 거리 공식을 바꾸지 않았습니다.
- 실제 2-1 승리73→75/+9G 정산, 1-5 보스 승리 후2-1 전체 화면 전환, 2-1→2-2 텍스트만 표시, 패배96→6의 하트/숫자만 표시 확인.
- 일반/특수14칸이 모두44×28px. 17개 아이템 초과 스크롤, 작은 슬롯의 클릭 툴팁·실제 드래그 장착·회수·삭제·복원 후17개 복구 확인.
- 1280/1366/1920/390px 화면과 모바일 패널 펼침에서 겹침·가로 스크롤 확인. 설정 버튼으로 v0.15.12 패치노트 열기 확인. 콘솔 경고/오류 없음.
- 테스트용 준비/전투 상태는 별도 localhost 원점의 임시 서버로 만들었으며 배포 소스에 포함하지 않았습니다.
