# AUTOCHESS — 노란색 전기 연쇄 타격 VFX 구현 지시서

- 문서 종류: Codex 전달용 디자인 레퍼런스 + 구현 프롬프트
- 작성일: 2026-11-17
- 상태: **VFX 외형·동작에 관한 사용자 승인 시안**. 실제 공격 판정이나 스킬 계수는 이 문서에서 확정하지 않음.
- 시각 레퍼런스: 같은 폴더 `AUTOCHESS_YELLOW_CHAIN_LIGHTNING_REFERENCE.html` (브라우저에서 열어 실행)

## 1. Codex에게 전달할 프롬프트 (복사하여 사용)

> 현재 AUTOCHESS 프로젝트의 기존 전투 렌더링 구조를 먼저 확인하고, 첨부된 HTML 레퍼런스의 **노란색 전기 연쇄 타격 VFX**를 실제 전투에 구현해 줘. 최초 발사는 **회색 직사각형 일반 탄환**이며 발사 지점에서 **노란 전기 스파클**이 짧게 퍼진다. 최초 대상에게 명중하면 **밝은 노란 섬광, 도트 파티클 및 광원**을 발생시키고, 실제 스킬 판정에서 지정된 주변 적 **최대 2명**에게 노란 계단식 번개가 연결되며 각각 별도의 명중 스파클이 발생한다. 사용자 승인된 기존 공통 VFX 원칙(선명한 사각 도트 / 광원 레이어 분리 / 부드러운 투사체 이동 / 파티클은 투명도가 아니라 개수 감소로 소멸)을 유지해 줘. **기존 공격 빈도, 표적 선택, 사거리, 피해 계산, 연쇄 대상·횟수 규칙, 전투 틱, 저장 데이터, 성능을 임의 변경하지 마.** 현재 코드의 실제 이벤트에 연결하고, 해당 연쇄 효과를 사용하는 공격에만 적용해 줘. 적이 0~1명만 추가로 있거나 표적이 사라진 경우에도 안전하게 동작해야 해. 정적인 이미지나 GIF 재생으로 대체하지 말고 JavaScript Canvas 기반으로 렌더링해 줘. 구현 후 실제 연결된 파일 및 변경 사항, 수동 검증 결과를 보고해 줘.

## 2. 완성 동작 레퍼런스

1. **발사**: 공격자의 발사 좌표에서 노란색/황금색 전기 도트 약 19개와 짧고 날카로운 스파크 선이 확산. 붉은색 불꽃이나 실물 화살 실루엣 **없음**.
2. **비행**: 탄환 본체는 **회색/밝은 회색의 짧은 막대**. 발사 후 대상까지 곧게 날아가며 프레임 보간으로 부드럽게 이동. 탄환 본체 자체가 번개가 되지는 않음.
3. **1차 명중**: 도착 위치에서 밝은 노란 섬광, 주황이 과하지 않은 금색 광원, 20~32개의 선명한 각진 픽셀이 외곽으로 확산.
4. **연쇄 타격**: 해당 공격/스킬의 실제 판정상 연쇄 적이 있다면 **최대 2명**에게 첫 명중 지점에서 계단식(지그재그) 노란 번개가 뻗음. 각각의 대상에 노란 타격 섬광과 픽셀 폭발을 동반. 화면에 2명이 없으면 빈 공간으로 번개를 그리지 않음.
5. **소멸**: 각 픽셀은 살아있는 동안 **완전 불투명하고 또렷함**. 정해진 수명이 끝나면 개별적으로 즉시 사라져 전체 도트 **개수가 줄어듦**. 부드러운 광원은 별도 레이어에서 감쇠 가능. 마지막에 잔광만 짧게 남고 종료.

### 공통 컬러 가이드 (제안값; 게임 팔레트에 맞춰 조정 가능)

| 요소 | 대표 색상 |
|---|---|
| 일반 탄환 | `#AAB2C0`, 밝은 중심 `#EFF3FA` |
| 전기 핵심 픽셀 | `#FFFBE2`, `#FFF093` |
| 노란 스파크 | `#FFD44E`, `#FFAD29`, `#FFEB7E` |
| 광원 중심 | 미색 `rgba(255,251,181,…)` |
| 광원 외곽 | 금색 `rgba(255,151,27,…)` |

### 동작 타이밍 (시연 레퍼런스용, 게임 속도에 맞게 조정)

| 단계 | 참고 시점 |
|---|---:|
| 발사 전기 스파크 | 60ms~360ms |
| 회색 탄환 비행 | 100ms~730ms |
| 최초 명중 | 약 730ms |
| 첫 번째 연쇄 전기 시작 | 약 930ms |
| 두 번째 연쇄 전기 시작 | 약 1030ms |
| 연쇄 대상 명중 파티클 | 약 1110ms / 1220ms |
| 잔광·파티클 정리 | 약 1500ms 이후 |

위 시점은 **연출 길이의 레퍼런스**이지 실제 게임의 공격 지연, 피해 판정 타이밍을 강제하는 값이 아님. 현행 엔진의 이벤트/애니메이션 속도에 맞추고, 시각 애니메이션 때문에 판정을 지연시키거나 중복시키지 말 것.

## 3. 구현 설계 원칙

- **시각 연출과 전투 로직을 분리**한다. 전투 로직이 발생시킨 `attack fired`, `primary hit`, `chain hit` 등의 기존 이벤트/콜백에만 VFX를 연결한다. 현재 프로젝트에 이벤트 버스가 없다면 구조에 맞는 최소 래퍼를 만든다.
- 발사 좌표·1차 명중 좌표·연쇄 대상 좌표는 **실제 게임 유닛 위치**에서 가져온다. HTML 레퍼런스의 3개 타깃 좌표는 데모 전용이다.
- 연쇄 타깃 선정은 **기존 스킬 로직**을 따른다. VFX가 가장 가까운 2명 등을 새로 계산하여 피해를 입히면 안 된다.
- Canvas 렌더러에서 투사체 직선 이동은 `requestAnimationFrame`의 시간 기반 보간. 시뮬레이션 틱(예: 100ms)에 종속된 뚝뚝 끊기는 움직임 금지.
- 렌더링 순서: 투명한 오버레이 Canvas → 광원(방사형 그라데이션 또는 blur) → 픽셀 투사체/스파크/번개. 타격 이펙트는 캐릭터가 가려지지 않도록 적절한 레이어에 그린다.
- 픽셀은 정수 좌표·작은 정사각형으로 선명하게 유지. 빛 번짐은 별도의 그라데이션/그림자로 처리. 픽셀 본체의 alpha fade 금지.
- 번개는 진행 방향에 따라 회전하는 꺾인 선분/픽셀 계단형 패스. 짧은 간격(예: 35~55ms)으로 가지의 모양이 재생성되는 스파클 느낌. 밝은 심선과 넓은 약한 광원을 분리.
- 파티클 오브젝트는 각기 수명·속도·위치를 가짐. 수명 종료 시 즉시 제거. 반복 재생·전투 종료·스테이지 변경 때 잔여 이펙트 정리.
- DPR 처리 및 `resize` 지원. 고해상도에서도 과도한 블러 없이 안정적으로 렌더링. 필요하면 이펙트 수 상한과 화면 밖 제거를 둔다.
- 탭 비활성/전투 일시정지/속도 변경/전투 종료 처리에 기존 프로젝트 정책을 적용. 리소스 누수 금지.
- 판정이 빗나감/회피/무효/타깃 소멸인 경우 기존 결과를 우선하며 **없는 명중을 시각적으로 만들어내지 말 것**. 발사 시점과 명중 시점이 달라질 때 연출을 조정한다.

## 4. 기존 게임에서 변경 금지

- 캐릭터·스킬 이름, 종족/직업/속성 및 유대
- 피해량, 치명타, 방어력, 회피, 마나·공격 속도 등 스탯 및 전투 판정
- 연쇄 타격 대상, 대상 수, 데미지 계수, 거리·사거리
- UI 레이아웃, 다른 속성 VFX, 상점/골드/레벨/아이템/저장 로직

## 5. 완료 조건 / QA

- [ ] 기존 일반 공격에서 회색 탄환이 정상 표시되며 발사 지점에 노란 전기 스파크가 나타남 (해당 속성 스킬에만).
- [ ] 첫 실제 명중 시 노란 섬광·파티클이 충분히 보임.
- [ ] 실존하는 연쇄 대상 2명에게 방향이 맞는 계단형 전기 효과와 각각 타격 이펙트가 출력됨.
- [ ] 연쇄 대상 1명/0명 및 표적 사망·삭제 시 오류나 허공 번개 없음.
- [ ] 픽셀 파티클은 투명도가 감소하는 대신 개별 삭제 방식으로 사라짐.
- [ ] 빛 번짐은 강하지만 도트 가장자리는 뭉개지지 않음.
- [ ] 투사체 이동이 부드럽고 공격·명중 판정과 어긋나지 않음.
- [ ] 초당 다수 유닛 공격에도 FPS 저하/이벤트 누수/잔상 누적이 없음.
- [ ] 전투 판정, 실제 피해량, 연쇄 수, 저장 동작 회귀 없음.
- [ ] 구현한 파일 목록, 선택된 스킬 연결 지점, 실제 테스트 결과가 패치노트에 기록됨.

## 6. 첨부 파일 안내

- `AUTOCHESS_YELLOW_CHAIN_LIGHTNING_REFERENCE.html`: 브라우저에서 실행되는 **Canvas 기반 레퍼런스**. 현재 사용자가 승인한 마지막 시안의 미학을 재현. HTML 내부에는 시연용 대상 3개가 고정 배치되어 있으며 이는 실제 로직이 아님.
- 이 MD와 HTML만으로 검토할 수 있으며, 실제 게임 연결은 프로젝트 코드의 공격/스킬 로직에 맞춰 수행해야 함.
