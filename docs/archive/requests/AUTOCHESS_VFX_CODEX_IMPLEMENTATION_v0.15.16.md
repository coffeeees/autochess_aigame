# AUTOCHESS — 기본 원거리 공격 VFX 구현 지시서

- 문서 유형: Codex 구현 요청서
- 대상: 현재 AUTOCHESS 웹게임 프로젝트
- 변경 범위: **기본 원거리 공격의 시각 효과(VFX)만**
- 기준: 기획 채팅에서 승인한 Canvas VFX 테스트(노란 막대 투사체 + 발사/명중 픽셀 파티클 + 확산 광원)
- 추가 요청: 동일 동작의 **회색 일반 화살/총알 버전** 제공
- 적용 버전: Codex가 현재 작업 중인 **실제 최신 코드**에 맞춰 적용. 문서에 적힌 수치는 테스트용 제안값이며 게임 밸런스 수치가 아님.

## 1. 목표

엔터 더 건전류의 간결하고 선명한 픽셀 VFX 감성을 참고하되, 특정 게임의 그래픽 자산을 복제하지 않는다.

1. 투사체 본체는 **아무 장식 없는 직선 막대 바** 하나다. 화살촉, 깃털, 탄피, 불꽃 꼬리, 궤적 이미지 등은 추가하지 않는다.
2. 투사체가 발사될 때와 적에게 명중할 때만 **작은 정사각형 픽셀 파티클**이 발생한다.
3. 발사/명중 순간 파티클 주변에는 **눈에 띄는 부드러운 빛 번짐(Glow/Bloom)**이 퍼진다. 단, 중심 픽셀 자체는 선명하게 유지한다.
4. 파티클은 이동하며 퍼지다가 **개수가 감소하며 하나씩 즉시 사라진다**. 파티클의 alpha를 점차 0으로 낮추는 페이드아웃은 하지 않는다.
5. **노란색 기본 버전**과 **회색 일반 원거리 버전** 두 종류를 제공하고, 외형 및 동작 로직은 공용화한다.
6. 모든 애니메이션은 게임의 전투 틱과 별개의 `requestAnimationFrame` + 경과시간 기반으로 자연스럽게 표현한다.

## 2. VFX 종류 및 색상

| 구분 | 색상 팔레트 예시 | 용도 | 기본 외형 |
|---|---|---|---|
| `yellow` | 바 `#FFBF26`, 중심 `#FFF08A`; 파티클 `#FFCF42`, `#FFD959`, `#FFAD39`, `#F16C32`, `#FFF0A0` | 녹스 등 노란색/화염계 기본 원거리 공격의 시험 적용 | 매끈한 **노란색 직사각형 바**, 발사/명중 시 금빛 픽셀과 주황색 광원 |
| `gray` | 바 `#ABB2BC`, 중심 `#E4E8EE`; 파티클 `#F1F3F6`, `#CFD5DF`, `#9CA5B3`, `#6D7787` | 일반 화살 또는 일반 총알 같은 비속성 원거리 기본 공격 | 동일한 **회색 직사각형 바**, 발사/명중 시 회백색 픽셀과 은회색 광원 |

> 위 두 버전의 차이는 **색상뿐**이다. 길이, 속도, 파티클 수, 퍼지는 방식, 수명은 동일한 기본 프로필을 사용한다. `gray`는 실제 화살/총알 실루엣을 그리지 않고 막대로 표현한다. **속성·직업에 따른 실제 자동 배정은 기존 코드/데이터 구조 확인 후 적용**하며, 잘못된 임의 매핑은 하지 않는다.

## 3. 연출 단계

### 3.1 발사 (Muzzle / Launch Burst)
- 실제 기본 공격의 **발사 이벤트/좌표**에서 한 번만 생성한다.
- 시작 시 약 **12~14개**의 작은 사각 파티클이 나타나고 다양한 각도로 빠르게 흩어진다.
- 중심에 순간적으로 강한 광원, 각 파티클 주변에는 약한 광원을 추가한다.
- 파티클별 수명을 조금씩 다르게 설정하고 해당 수명에서 **즉시 삭제**한다.
- 권장 수명 범위: 약 **135~270ms**. 광원은 이 짧은 순간 동안 확장되거나 광원이 남은 파티클에 연동되도록 한다.

### 3.2 비행 (Projectile)
- 길쭉한 **단색 막대 바**로만 표현한다(기준 약 **32×8 렌더 단위**, 화면 배율에 따라 조정).
- 공격자에서 목표 지점까지의 방향으로 바를 회전시킨다. 대각선/상하 방향도 지원한다.
- 코어가 필요한 경우 막대 내부에 단색의 밝은 줄 정도만 사용하고, **화살 모양·불꽃·별도 비행 파티클·꼬리 이펙트는 넣지 않는다**.
- 발사와 명중 사이 위치는 매 렌더 프레임의 경과시간(`deltaTime`)을 사용해 보간한다. 기존 0.1초 전투 틱으로 화면 좌표를 순간 이동시키지 않는다.
- 기존 실제 전투 판정(명중, 회피, 투사체 속도, 대미지, 타이밍)을 바꾸지 않는다. **시각 효과의 이동 시간은 기존 공격 이벤트/투사체 상태와 동기화**한다.

### 3.3 명중 (Impact Burst)
- **실제 명중 또는 충돌 이벤트의 좌표**에서 한 번만 생성한다.
- 권장 **18~22개**의 픽셀을 발사 때보다 넓고 빠르게 사방으로 확산한다.
- 중심부는 짧게 강하게 발광하고 광원 반경이 확장된다. 잔광과 개별 픽셀 광원은 실제로 남아 있는 픽셀에 연동한다.
- 픽셀은 완전 불투명한 상태를 유지하다가 개별 수명(권장 약 **145~360ms**) 종료 시 바로 삭제한다.
- MISS/회피/방어 등 기존 이벤트의 구분을 존중한다. **맞지 않은 공격을 명중 이펙트로 표시하지 않는다.** 기존 코드가 이벤트를 제공하지 않는 경우 임의 판정을 만들지 말고 기존 구조에서 합리적인 표시 지점을 찾는다.

## 4. 렌더링 원칙

- 권장: 기존 전장 Canvas 렌더링에 **VFX 전용 레이어**를 추가하거나 해당 Canvas 렌더 루프에 안전하게 통합한다. 게임이 DOM 기반이면 전장 위 투명 Canvas 오버레이도 가능하다.
- 좌표는 **보드 좌표 → 실제 화면 좌표** 변환을 기존 카메라/보드 크기 계산과 연동한다. 7열×8행 전장 구조, 반응형 크기와 확대 설정에서 위치가 어긋나면 안 된다.
- 픽셀 본체는 `fillRect` 등으로 **정수 좌표에 맞춰 선명하게** 그린다. 필요한 경우 `imageSmoothingEnabled = false`를 쓴다.
- 광원만 별도 패스로 렌더링한다. 예: radial gradient 혹은 `shadowBlur`/`lighter` 합성. 본체 픽셀까지 블러 처리하지 않는다.
- 광원이 과도하게 누적되어 화면을 하얗게 만들지 않도록 밝기와 중첩을 제한한다. 테마에 따라 `yellow`와 `gray`의 광원 색은 독립적으로 조절한다.
- 광원 자체의 강도/반경 변화는 허용하나 **파티클 도트가 서서히 투명해지는 연출은 금지**한다.
- 기기 성능/다수의 동시 전투에 대비해 이펙트 풀, 객체 재사용, 가시 영역 밖 처리, 동시 파티클 상한 등을 고려한다.
- 브라우저 탭 비활성화, 일시정지, 전투 종료, 스테이지 전환 시 VFX가 남거나 과도한 `deltaTime`이 누적되지 않도록 처리한다.

## 5. 권장 기본값 (게임 밸런스와 무관한 시각 효과 튜닝용)

| 항목 | 권장 시작값 | 비고 |
|---|---:|---|
| 투사체 바 크기 | 32×8 렌더 단위 | 전장 실제 표시 크기에 따라 비례 조정 |
| 발사 파티클 수 | 14개 | 작은 정사각형, 2~6px 수준 |
| 명중 파티클 수 | 22개 | 작은 정사각형, 2~5px 수준 |
| 발사 효과 표시 | 약 0.25~0.35초 | 개별 픽셀 소멸 |
| 명중 효과 표시 | 약 0.3~0.4초 | 개별 픽셀 소멸 |
| 발사/명중 광원 | 중심 강함 + 개별 픽셀 약함 | 반경 및 밝기는 테스트 후 조절 |
| 시각 갱신 | `requestAnimationFrame` | 전투 틱과 독립 |

**중요:** 이전 테스트의 비행 0.8~0.9초 및 자동 반복 1.7초는 **미리보기 데모용** 타이밍이다. 실제 게임의 공격 속도, 명중 시점, 공격 주기는 이 숫자로 강제 변경하지 않는다.

## 6. 코드 구조 권고

공용 구성 예시(실제 프로젝트 구조에 맞게 조정):

```js
const BASIC_RANGED_VFX = {
  yellow: {
    bar: '#FFBF26', core: '#FFF08A',
    particles: ['#FFCF42', '#FFD959', '#FFAD39', '#F16C32', '#FFF0A0'],
    glow: 'orange'
  },
  gray: {
    bar: '#ABB2BC', core: '#E4E8EE',
    particles: ['#F1F3F6', '#CFD5DF', '#9CA5B3', '#6D7787'],
    glow: 'silver'
  }
};
```

- 시각 효과 함수는 `spawnLaunchVfx(position, theme)`, `spawnProjectileVfx(start, target, theme, combatEvent)`, `spawnImpactVfx(position, theme)`처럼 **공용 구조**로 구성한다(함수명은 예시).
- 발사→비행→명중의 **각 단계는 이벤트를 기준으로 생성**하고, 중복 호출·중복 타격 효과가 생기지 않도록 한다.
- 색상 테마만 갈아 끼우면 같은 애니메이션이 나와야 한다.
- 실제 VFX 연결 지점, 좌표계, 공격 이벤트 구조는 Codex가 **기존 소스를 먼저 확인**해 정한다.

## 7. 반드시 유지할 기존 기능

- 피해량 및 AD/AP/GD/치명타/회피 등 전투 계산
- 사거리, 공격 대상 선택, 타격 시점, 공격 속도 및 이동/경로탐색
- 적/아군 판정, 승리·패배, HP, 보상, 스테이지 진행
- 전투 Worker 및 시간 진행 처리(프로젝트에 구현되어 있는 경우)
- 아이템/유대/증강/스킬 로직, 저장·불러오기
- 기존 UI 레이아웃, 캐릭터 이미지, 전장 격자 수

본 요청은 **그래픽/시각화 구현**이며 게임 규칙·밸런스 변경 요청이 아니다. 일반 근접 공격이나 특수 스킬의 기존 연출은 요청 없이 일괄 교체하지 않는다.

## 8. 검증 및 완료 조건

- [ ] 노란색 버전: 선명한 노란 막대가 이동하고, 발사·명중 순간 금빛 도트와 퍼지는 광원이 발생한다.
- [ ] 회색 버전: 똑같은 모션으로 회색 막대/회백색 파티클/은회색 광원이 나온다.
- [ ] 막대는 화살촉, 불꽃, 트레일 등 불필요한 장식이 없다.
- [ ] 살아 있는 도트는 불투명하며, 시간에 따라 **도트 수가 줄어들어** 완전히 사라진다.
- [ ] 픽셀은 선명하고 광원만 부드럽다.
- [ ] 두 테마에서 공격 방향 변화(수평·수직·대각선), 여러 유닛 동시 공격이 정상이다.
- [ ] 명중 여부/타격 위치/발사 시점과 VFX가 일치한다.
- [ ] 전투 일시정지·종료·다음 스테이지 이동 후 이펙트가 잔류하지 않는다.
- [ ] 전장 크기 조정/브라우저 크기 변경 시 위치 및 비율이 유지된다.
- [ ] 기존 게임 밸런스와 시스템이 변경되지 않는다.
