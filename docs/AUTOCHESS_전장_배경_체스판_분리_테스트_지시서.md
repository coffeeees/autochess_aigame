# AUTOCHESS — 배경 이미지 / 체스판 이미지 분리 테스트 지시서

- **대상 버전:** v0.15.5 (사용자가 전달한 최신 완료 패치노트 기준)
- **작업 성격:** 전장 UI 렌더링 구조 변경 및 시각적 테스트
- **우선순위:** 기능 유지 > 이미지 분리 > 전장 확대 및 가독성
- **기준 화면:** 사용자가 제공한 **1920×1080 스크린샷** (기존 이미지가 중앙에만 나타나고 주변에 빈 공간이 보이는 상태)

## 1. 문제와 목표

현재 배경 풍경과 체스판이 한 이미지에 결합돼 있어, 체스판 크기만 독립적으로 조절하기 어렵다. 1920×1080 화면에서는 중앙의 합성 이미지 주변에 빈 공간이 많고 전장 크기를 충분히 활용하지 못한다.

이번 테스트에서는 **배경 이미지와 체스판 이미지를 별도 에셋/레이어로 분리**하여,

1. 배경은 게임 화면 뒤쪽에 자연스럽게 채워 넣고,
2. 체스판은 배경과 무관하게 **위치와 크기를 독립적으로 조절**하며,
3. 1920×1080 기준 **현행보다 체스판을 조금 더 크게** 보이게 하고,
4. 캐릭터 배치·전투·상점·아이템 등 기존 기능은 그대로 유지한다.

> **주의:** 이전 v0.15.5 패치노트의 `1672×941 원본 배경`, `x461~1211/y93~824 격자 고정 좌표`는 **기존 일체형 이미지에 맞춘 과거 구현 값**이다. 새 분리 구조에서 필수로 유지할 규격이 **아니다**. 다만 실제 게임의 **7열 × 8행 보드**와 **아군 아래 4행**은 유지한다.

## 2. 제공 에셋 및 역할

- **배경 이미지 1장:** 고대 유적·푸른 하늘·아치·붉은 깃발·횃불 분위기의 풍경 이미지. **전장 격자, 캐릭터, UI는 포함하지 않는** 배경 전용.
- **체스판 이미지 1장:** 석조 테두리와 어두운 파란색 판면, 푸른 격자를 포함하는 **별도 전장 오버레이 PNG**. **체스판 외부 영역은 투명해야** 하며 배경 위에 합성한다.

두 이미지는 사용자가 Codex 작업 공간에 전달/등록할 예정이다. **실제 파일명과 경로는 프로젝트에 등록된 이름을 사용**하고, 임의의 파일명을 하드코딩하지 말 것.

**에셋 수락 전 확인:**
- 체스판 PNG의 **알파 채널과 외부 투명 여백**을 확인한다. 검정색 픽셀이 실제 배경으로 들어 있다면 투명이 아니므로 수정이 필요하다.
- 이미지에 보이는 격자가 **정확히 7열 × 8행**인지 확인한다. 이미지 생성 결과가 다를 경우 무리하게 논리 좌표를 맞추지 않는다.
- 이미지 바깥 테두리/격자 위치를 실측하고, 화면상의 실제 히트박스와 맞는지 점검한다.
- 투명 이미지나 격자 정합성이 충분하지 않으면 **실제 격자를 CSS/SVG/HTML에서 그리는 대안**을 적용하거나 문제를 보고한다. 이미지의 장식만 사용해도 된다.

## 3. 권장 화면 레이어 구조

아래 순서대로 렌더링하되, 현재 프로젝트의 컴포넌트 구조에 맞게 조정할 수 있다.

1. **Background Layer** — 전장 구역의 분위기용 배경 이미지. 이미지의 원본 비율을 유지하며 영역을 자연스럽게 채운다(예: `background-size: cover`). 일부 가장자리 크롭이 발생할 수 있으니 중심부와 주요 장식이 부자연스럽지 않게 조절한다.
2. **Board Frame / Art Layer** — 투명 PNG 체스판 이미지. 배경과 독립된 크기·중앙 정렬·위치 조정이 가능해야 한다.
3. **Board Grid / Interaction Layer** — **7×8 논리 그리드**와 칸별 클릭/드래그/드롭 판정 영역. 아군 배치 가능 범위는 아래 4행. 이미지 내 격자와 정확히 겹쳐야 한다. 필요하면 격자선 자체는 코드 기반으로 렌더링한다.
4. **Unit / Effects Layer** — 캐릭터, 이동 연출, 투사체, 피해 숫자 등. 위 논리 그리드의 칸 중심 좌표를 공유한다.
5. **기존 HUD 및 UI 패널** — 좌측 조합, 우측 인벤토리, 상단 정보, 하단 대기석·버튼. 동작과 정보가 가려지지 않도록 유지한다.

이미지 크기에 따라 로직의 보드 칸 수나 저장 데이터가 달라져서는 안 된다. **크기 변경은 시각적 스케일 및 좌표 매핑만 변화**시킨다.

## 4. 레이아웃 요구사항

- **1920×1080을 우선 테스트 기준**으로 사용한다.
- 현재보다 전장 그리드를 적당히 키워 가독성을 개선한다. **확대 배율과 목표 픽셀 크기는 테스트 화면을 비교해 정하고, 임의 수치를 확정 사양으로 삼지 않는다.**
- 확대 후에도 상단 HUD, 좌측 조합, 우측 보관함, 하단 대기석·레벨·영입·전투 시작 버튼이 가려지거나 겹치지 않아야 한다.
- 배경은 빈 공간이 두드러지지 않게 자연스럽게 채우되, 게임 정보 위로 올라오지 않아야 한다.
- **전장 전체 이미지의 CSS 크기**와 **실제 7×8 타일 그리드 영역**은 다를 수 있다. 석조 테두리 등 장식 여백을 타일로 취급하지 않는다.
- 비율을 찌그러뜨리지 않고 확대/축소한다. 화면 크기가 줄어들면 보드와 패널이 충돌하지 않도록 조정하고, 필요한 경우 안전하게 보드 크기를 축소한다.
- 브라우저 리사이즈 후에도 격자와 캐릭터의 정렬이 유지되어야 한다.

## 5. 기능 유지 및 비범위

**이번 작업에서 변경하지 말 것**

- 전장 논리 구조 **7열 × 8행**, 아군 배치 **아래 4행**
- 대기석 **10칸**, 상점 영입 팝업, 선택 증강 표시, 아이템 보관함 및 장착
- 캐릭터 이동·교체·드래그 앤 드롭·공격·스킬·소환·전투 결과
- 골드, 레벨/XP, 보상, 확률, 증강, 아이템, 세이브·이어하기 관련 게임 규칙
- 현재 정상적으로 작동하는 UI의 기능과 조작 흐름

이번 단계에서 **이미지 스킨의 최종 디자인이나 이미지 해상도 표준은 확정하지 않는다.** 두 에셋은 분리 구조 검증을 위한 테스트 이미지다.

## 6. 테스트 및 확인 항목

- [ ] 배경 이미지와 체스판 PNG가 **독립적으로 표시·크기 조절**된다.
- [ ] 체스판 PNG 외부가 **실제 투명**하여 뒤 배경이 보인다.
- [ ] 7열×8행, 총 56칸의 시각적 격자와 실제 클릭/드롭 좌표가 일치한다.
- [ ] 하단 4행에만 아군을 배치할 수 있다.
- [ ] 캐릭터를 다른 칸으로 이동하거나 교체할 때 이미지와 좌표가 어긋나지 않는다.
- [ ] 전투 중 이동·투사체·피해 표시가 새 보드 위치에서 정상 정렬된다.
- [ ] 1920×1080에서 기존보다 체스판이 더 크게 보이고, 주변 배경도 자연스럽게 채워진다.
- [ ] 상단·좌측·우측·하단 UI를 가리지 않으며 기능이 정상이다.
- [ ] 다른 창 크기에서도 비율 왜곡이나 불필요한 겹침이 없다.
- [ ] 기존 저장 데이터와 게임 계산은 유지되며 회귀 오류가 없다.

## 7. Codex 작업 결과 보고 요청

구현 후 다음 사항을 짧게 보고할 것.

1. 변경한 파일 및 **이미지 경로**
2. 배경/체스판/논리 격자/캐릭터가 어떻게 분리되었는지
3. 1920×1080 기준 새 보드의 **화면상 크기와 위치**, 기존 대비 확대 정도
4. 투명 PNG 및 **7×8 격자 정렬 검증 결과**
5. 테스트 결과와 남아 있는 문제

**완료 기준:** 단순히 이미지 두 장이 보이는 것이 아니라, **배경과 보드를 독립 조절하면서 7×8 입력·배치·전투 위치가 정확히 맞는 상태**다.
